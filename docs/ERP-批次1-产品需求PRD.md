## 0.1 三个必须先定的产品口径（本文已定，开发照做）

| # | 问题 | 本文的定法 | 为什么这么定 |
|---|---|---|---|
| **D1** | 单价录入口径：含税还是不含税 | **默认"不含税单价"录入**，单据头可一键切换为"含税"，切了字面数字就变含义（见 3.1） | 存货成本按**不含税**入账（进项税不进成本），成本核算与凭证都拿不含税金额，少一层倒算就少一类尾差；且第五章验收数字（200/26/226）就是按不含税 2 元算出来的 |

# 一、用户角色与真实场景

## 1.1 角色总览

| 角色 | 典型岗位 | 系统身份（复用现有 RBAC，**不另建用户体系**） | 核心诉求 | 频率 |
|---|---|---|---|---|
| **采购员** | 采购部业务员 | `sys_user` + 角色 `ERP_BUYER` | 录单快、知道哪张单还没到货、能催 | 每天多次 |
| **仓管员** | 仓库管理员 | `sys_user` + 角色 `ERP_KEEPER` + **仓库指派** | 到货 30 秒收完、库存一眼看清、账实能对上 | 每天多次 |
| **财务会计** | 总账/应付会计 | `sys_user` + 角色 `ERP_ACCOUNTANT` | 应付对不对、凭证能不能自动出、总账能不能查 | 每天 |
| **财务主管** | 财务经理 | `sys_user` + 角色 `ERP_FIN_MGR` | 审凭证、看科目余额、揪异常 | 每周 |
| **老板/管理层** | 总经理、部门负责人 | `sys_user` + 角色 `ERP_VIEWER`（只读） | 买了多少、压了多少库存、还欠多少钱 | 每周/每月 |

> **一条硬规则**：以上 5 个角色全部是 `sys_role` 的普通记录 + 权限码组合，用户、部门、角色、菜单、字典全部复用现有 `system/*` 模块。ERP 侧**唯一新增的关联表**是"用户↔仓库"（5.3.2），因为现有模型里没有"这个人管哪个仓库"的表达能力。

## 1.2 端到端故事

### A. 采购员 小王

**A1 — 从"要买螺丝"到"单子交出去"（主链路，也是第七章验收场景 1 的来源）**

车间报上来"螺丝 M6×20 快没了，再买 100 件"。小王打开 `ERP → 采购管理 → 采购订单`，点右上「+ 新建采购订单」：

1. 表头选供应商「宁波精工五金（SUP-000001）」，系统自动带出**账期 30 天**、**应付科目 2202.01 应付账款-货款**、税率 13%。
2. 下单日期默认今天 2026-10-08，交货日期填 2026-10-15，币种 CNY（本批锁定）。
3. 明细区点第一行：物料选「螺丝 M6×20（MAT-000001）」，系统带出**单位=件、税率=13%、存货科目=1405 库存商品、默认仓库=WH-01 主仓**；数量敲 `100`，单价敲 `2`，金额立刻显示 `200.00`、税额 `26.00`、价税合计 `226.00`；底部合计条同步变成 `226.00`。
4. 回车到下一格继续录第二行（体验细节见 4.4.4）。录完点「保存草稿」→ 单号 `PO-202610-0001`。
5. 复核一遍，点「提交」，状态变「已提交」。**提交后这行就进了仓管员的"待到货"视野**。

> 关键体感：小王全程不碰税率、不算税、不选科目——**这些从主数据带出**，他只需要"选物料 + 填数量 + 填单价"。

**A2 — 周五下午的催货（跟单场景）**

小王在 `采购订单` 列表把状态筛成「已提交 + 部分到货」，勾上「只看我的」，看到 `PO-202610-0001` 只到货了 60 件，未收 40 件。他点行尾「查看未清明细」→ 弹出未到货清单（物料/订购 100/已收 60/未收 40/需求日期 10-15，**已逾期 3 天**标红）。他照着这条去打供应商电话——这是本批唯一需要的"跟供应商"能力，**不做供应商门户、不做邮件催货**。

### B. 仓管员 李姐

**B1 — 到货 30 秒入库**

供应商货车到门，李姐打开 `ERP → 库存管理 → 收货入库`，点「+ 新建入库单」→ 弹窗问「是否从采购订单生成？」→ 选「从订单生成」→ 搜索 `PO-202610-0001` → 系统把**未收数量 100 件自动填进明细**（数量可改小，改大超收会被拦）。

她核对实物：螺丝 100 件，对得上。仓库 `WH-01 主仓` 已经默认带出。点「保存」→ 单号 `GR-202610-0001`，状态「草稿」。再点「过账」→ 确认弹窗（见 4.3.4）把**要影响的库存、要生成的应付、要生成的 3 行凭证**全列出来，她确认无误点「确认过账」。

3 秒后：单子变「已过账」，`ERP → 即时库存` 里螺丝 M6×20 主仓从 0 变 100，结存单价 2.000000，结存金额 200.00。

**B2 — "账上说有 100，货架上只有 40"（对账场景）**

李姐发现货架不对，打开 `库存流水`，筛物料=螺丝 + 仓库=主仓，看到两条记录：
`2026-10-15 GR-202610-0001 +100 结存 100`、`2026-10-20 GR-202610-0004 +100 结存 200`。
再看 `即时库存` 显示 200——说明**不是系统少了，是有人领走了 160 件没开单**（本批无出库单，属第 3 批生产领料范畴）。她能把话说明白，这就是本批"流水可追溯"的价值。

### C. 财务会计 张会计

**C1 — 月底不用手工做采购凭证了**

张会计打开 `ERP → 财务管理 → 凭证查询`，期间选 2026-10，来源筛「自动-入库」。6 张入库单对应的 6 张凭证全在，双击任意一张看到分录：

```
记-202610-0001   凭证日期 2026-10-15   来源：入库单 GR-202610-0001
借  1405 库存商品                      200.00   [物料 MAT-000001｜仓库 WH-01]
借  2221.01.01 应交税费-应交增值税(进项税额)  26.00
贷  2202.01 应付账款-货款              226.00   [供应商 SUP-000001]
                                合计：借 226.00 = 贷 226.00 ✅
```

她原本每月要花半天从入库单里抄这几笔，现在只需**抽查**：点「总账查询」选 1405 库存商品，本期借方 1,200.00，和入库单不含税金额合计对得上，收工。

**C2 — 有一张入库单是错的**

发现 `GR-202610-0002` 收错仓库了（本该收主仓，收成了次仓）。她**不能改也不能删**，去找仓管员：请仓管员作废该入库单（走红冲），再重新从订单生成一张正确的入库单。她在凭证查询里能看到 `记-202610-0007`（红字，金额负数）和新的 `记-202610-0008`，两张相加等于正确金额。

> 这条决定了产品的核心态度：**已过账的单据一律不可改，只能作废红冲**，见 3.7。

### D. 财务主管 陈主管

**D1 — 审手工凭证**

出纳手工提了一张"计提本月水电费"的凭证（草稿）。陈主管在 `凭证查询` 筛状态=草稿，点开看分录，借贷平衡、科目是末级、金额合理，点「审核」→ 状态变「已审核」。这张凭证此后才允许「记账」进总账（自动凭证不需要他审，见 3.3 的说明）。

**D2 — 月度科目余额一眼扫异常**

打开 `ERP → 财务管理 → 科目余额表`，期间 2026-10：
- 1405 库存商品：期初 0 / 本期借 1,200.00 / 本期贷 0 / 期末 1,200.00（借方）
- 2202.01 应付账款-货款：期初 0 / 本期借 0 / 本期贷 1,356.00 / 期末 1,356.00（贷方）
- 2221.01.01 进项税额：本期借 156.00

他盯一眼 `库存商品期末 1,200.00` 与 `应付期末 1,356.00` 的差额 = 156.00 = 进项税，**勾稽关系成立**，签字。

### E. 老板 王总（只读）

**E1 — 三个数**

王总没有"过账""新建"任何按钮，只看到 3 个列表：`即时库存`（当前库存金额合计 = Σ 结存金额）、`应付清单`（未付合计）、`采购订单`（本月采购金额合计 = Σ 价税合计）。他筛 2026-10，一眼得出：本月买了 1,356 元货，库存压着 1,200 元（不含税），还欠供应商 1,356 元。

> 本批**不做**任何图表、驾驶舱、报表导出（那是第 4 批）。老板看到的就是这三个列表底部的合计行。

# 三、关键业务规则（开发依据，逐条给公式与算例）

## 3.0 规则总览

| # | 规则 | 一句话结论 | 主要影响 |
|---|---|---|---|
| 3.1 | 金额口径 | **默认按不含税单价录入**，可切含税；增值税按**价外税**算，三个金额恒等 | 订单/入库单明细、应付、凭证 |

## 3.1 金额口径（价内税 / 价外税 / 三种金额恒等）

### 3.1.1 事实前提：中国增值税是**价外税**

增值税不含在商品价格里，是"价款之外另收"的税。所以一笔采购必然有**三个金额**，且恒满足：

```
价税合计（应付多少） = 不含税金额（价款，进成本） + 税额（进项税，可抵扣，不进成本）
```

**这条是本章的地基**：库存成本只吃"不含税金额"，应付吃"价税合计"，进项税单独进 `2221.01.01`。

### 3.1.2 字段口径（全系统统一，不得各页自定义）

| 字段 | 含义 | 精度 | 说明 |
|---|---|---|---|
| `qty` | 数量 | **4 位小数** | 展示时去掉无意义的尾 0（100.0000 → 100） |
| `price_excl` | **不含税单价** | **6 位小数**（入库 6 位，界面默认显示 4 位） | 成本核算与凭证借方用它算出的金额 |
| `price_incl` | 含税单价 | 6 位小数 | 由 `price_excl × (1+税率)` 派生，不单独存权威值 |
| `amount_excl` | 不含税金额（价款） | **2 位小数** | 进存货成本 |
| `tax_amount` | 税额 | **2 位小数** | 进进项税科目 |
| `amount_incl` | 价税合计 | **2 位小数** | 进应付 |
| `tax_rate` | 税率（%） | 2 位小数 | 0 / 1 / 3 / 6 / 9 / 13（本批常见 13、9、6、0） |

### 3.1.3 两种录入口径与计算公式

单据头有一个 `tax_mode` 开关，**默认 `2=不含税`**（本文 D1 决策）：

**口径 A：不含税单价录入（默认，主路径）**

```
amount_excl = round(qty × price_excl, 2)              ← 先定价款
tax_amount  = round(amount_excl × tax_rate / 100, 2)   ← 再按价款计税（符合"不含税销售额×税率"）
amount_incl = amount_excl + tax_amount                 ← 加法得出，不再舍入
```

**口径 B：含税单价录入（供应商报价就是含税价时切过来）**

```
amount_incl = round(qty × price_incl, 2)                        ← 先定价税合计
amount_excl = round(amount_incl / (1 + tax_rate/100), 2)         ← 倒算价款
tax_amount  = amount_incl - amount_excl                          ← 用减法倒挤，保证三者和恒等
```

> **为什么口径 B 的税额必须用减法而不是再乘一次税率**：如果 `tax = round(amount_excl × rate, 2)`，会出现 `amount_excl + tax ≠ amount_incl` 的 1 分钱差额，凭证借贷就不平了。**减法倒挤是唯一能保证恒等的写法。**

### 3.1.4 算例：同样敲"2 元"，两种口径差 26 元

以"螺丝 M6×20，100 件，单价 2 元，税率 13%"为例（已用计算器核验）：

| 口径 | 输入 | 价款 `amount_excl` | 税额 `tax_amount` | 价税合计 `amount_incl` | 入库成本 | 应付 |
|---|---|---|---|---|---|---|
| **A 不含税（默认）** | 单价 2.000000 | **200.00** | **26.00** | **226.00** | 200.00 | 226.00 |
| B 含税 | 单价 2.000000 | 176.99 | 23.01 | 200.00 | 176.99 | 200.00 |

验算（口径 A）：`100 × 2 = 200.00`；`200.00 × 13% = 26.00`；`200.00 + 26.00 = 226.00` ✅
验算（口径 B）：`100 × 2 = 200.00`；`200.00 ÷ 1.13 = 176.991150… → 176.99`；`200.00 − 176.99 = 23.01` ✅

**⚠️ 同样的"2"，价款差 23.01、应付差 26.00。** 所以：
- 单据头必须常驻一个口径徽标：`[不含税]` / `[含税]`，深浅蓝底白字，**不许省略**；
- 点徽标切换时弹确认框：「切换为含税录入后，所有行将按各行税率重新计算金额，是否继续？」，切换后重新渲染单价列；
- 列表页的"金额"列默认显示**价税合计**并在表头注明 `金额(价税合计)`，避免两个人对着同一张单说不同数。

### 3.1.5 汇总与尾差

```
单据 amount_excl 合计 = Σ 各行 amount_excl   （先逐行舍入到 2 位，再相加）
单据 tax_amount  合计 = Σ 各行 tax_amount
单据 amount_incl 合计 = Σ 各行 amount_incl
```
**禁止**"先把各行未舍入金额加总再一次性舍入"——那样单据合计会与凭证各行之和差 1 分钱，凭证就不平了。凭证一律以**行合计**为准。

### 3.1.6 边界

| 场景 | 处理 |
|---|---|
| 税率 0（免税/不征税） | `tax_amount = 0`，凭证只有 2 行（借存货 / 贷应付），不产生进项税行 |
| 单价为 0（赠品/样品） | 允许，`amount_excl = 0`，凭证仍生成（金额 0 的行照常写，便于追溯；若整单金额全 0，则**不生成**凭证并在入库单详情提示"本单金额为 0，未生成凭证"） |
| 负单价（退货冲销用） | 本批**禁止**在订单/入库单填负数，退货走作废红冲（3.7） |
| 一张单多税率 | 允许。各行按各自税率算，进项税在凭证中**按税率汇总成多行**（见 3.4.6） |
| 数量为 0 的行 | 保存草稿允许，提交/过账时拦截："第 3 行数量为 0，请删除或填写数量" |

## 3.2 成本核算法（移动加权平均）

### 3.2.1 方法选择

采用**移动加权平均法**（《企业会计准则第 1 号——存货》允许的计价方法之一）。选择理由：
- 本系统按"每笔入库即时重算单价"，符合移动加权的定义；
- 与"库存金额随时可查"的产品诉求一致（月末一次加权平均做不到随时查单价）；
- 实施简单、无需批次追溯。

`物料.计价方式` 字段保留枚举 `1=移动加权平均 / 2=先进先出 / 3=个别计价`，**本批只允许选 1**；选 2/3 时前端置灰并提示"该计价方式将在后续批次支持"。已产生库存后禁止修改计价方式。

### 3.2.2 核算维度：物料 × 仓库

每个 （物料, 仓库） 组合独立维护一行结存：

| 字段 | 精度 | 说明 |
|---|---|---|
| `qty` | 4 位 | 现存量 |
| `amount` | 2 位 | 结存金额（**权威值**） |
| `avg_price` | 6 位 | 结存单价（**展示与出库计价用，不是权威值**） |
| `locked_qty` | 4 位 | 锁定量（本批恒 0，为第 2 批销售占用预留） |

可用量 `available_qty = qty − locked_qty`（本批 = `qty`）。

### 3.2.3 入库过账时的重算公式

```
new_qty    = old_qty + in_qty
new_amount = old_amount + in_amount                     ← 金额用加法，绝不用「单价×数量」重算
new_avg    = round(new_amount / new_qty, 6)    (new_qty > 0 时)
```

> **核心设计**：`amount` 永远是"上一笔金额 + 本次金额"累加出来的，`avg_price` 只是除出来的一个**参考值**。这样无论小数怎么除不尽，**结存金额永远不会漂移**，库存金额与总账 `1405` 科目余额天然对得上。

### 3.2.4 出库/冲回时的公式（本批只用于作废冲回，第 2 批用于销售出库）

```
普通出库： out_amount = round(out_qty × avg_price, 2)
          new_amount = old_amount − out_amount
清仓出库（new_qty 将变为 0）：out_amount = old_amount     ← 倒挤，把剩余尾差一次带走
          new_amount = 0.00
冲回入库（作废）：out_qty = 原入库数量，out_amount = 原入库金额（不是按现价算，见 3.7.2）
```

### 3.2.5 算例

**算例 1（对应第七章验收场景 4）：两批不同价入库**

| 步骤 | 业务 | 数量变动 | 金额变动 | 结存数量 | 结存金额 | 结存单价（6 位） |
|---|---|---|---|---|---|---|
| 0 | 初始 | — | — | 0 | 0.00 | — |
| 1 | 入 100 @ 2.00（不含税） | +100 | +200.00 | 100 | 200.00 | 200.00/100 = **2.000000** |
| 2 | 入 100 @ 3.00（不含税） | +100 | +300.00 | 200 | 500.00 | 500.00/200 = **2.500000** |

✅ 结存 200 件、单价 2.500000、金额 500.00 —— 与验收要求一致。

**算例 2：除不尽的尾差怎么处理**

| 步骤 | 业务 | 数量 | 金额 | 结存数量 | 结存金额 | 结存单价 |
|---|---|---|---|---|---|---|
| 1 | 入 10 @ 1.11 | +10 | +11.10 | 10 | 11.10 | 1.110000 |
| 2 | 入 3 @ 3.33 | +3 | +9.99 | 13 | **21.09** | 21.09/13 = 1.6223076923… → **1.622308** |

注意：`13 × 1.622308 = 21.090004`，与结存金额 `21.09` 差 0.000004——**这个差永远不修**，因为结存金额 21.09 才是权威值（加法得出），单价只是展示用的近似值。金额与数量在系统中始终自洽：总账余额 = Σ 结存金额 = 21.09。

**算例 3：结存单价变了，再作废早期入库单**

| 步骤 | 业务 | 结存数量 | 结存金额 | 结存单价 |
|---|---|---|---|---|
| 1 | 入 100 @ 2.00（GR-001） | 100 | 200.00 | 2.000000 |
| 2 | 入 100 @ 3.00（GR-002） | 200 | 500.00 | 2.500000 |
| 3 | 作废 GR-001（冲回 −100 / −200.00） | 100 | **300.00** | 300.00/100 = **3.000000** |

✅ 正确：冲回的是"当初进来的那 200 元"，剩下的 100 件自然回到单价 3.00。**不能按当期 2.5 的单价冲回**（那会多退 50 元，库存金额与总账立刻错位）。

### 3.2.6 边界

| 场景 | 处理 |
|---|---|
| 同一物料在一张入库单出现多行 | 按行顺序逐行累加。结果与合并成一行一致（因为都是加法），不做特殊处理 |
| 仓库允许负库存且当前结存为负/零，又入库 | `old_qty ≤ 0` 时，`new_avg = 本次入库单价`（重置，因为旧的成本基准已失效），同时写一条告警日志：「物料 X 在仓库 Y 入库时结存为负（-5），单价已重置为 2.000000」 |
| 入库数量为 0 | 直接拒绝，不产生流水 |
| 结存金额出现极小负数（如 -0.01） | 只有清仓时可能出现，已用"倒挤"消除；若仍出现则强制归零并记日志 |
| 成本重算并发 | 过账时对 （item_id, warehouse_id） 行加 `SELECT … FOR UPDATE` 行锁，**按 item_id 升序**加锁避免死锁 |

## 3.3 凭证生成时机（本 PRD 最关键的一个决策）

### 3.3.1 三个方案对比

| 方案 | 做法 | 好处 | 坏处 | 结论 |
|---|---|---|---|---|
| **A 入库即生成（票货同行）** | 入库过账时立刻生成「借存货 + 借进项税 + 贷应付」并直接记账 | ① 库存与总账永远同步，随时查都是平的 ② 财务零手工 ③ 本批能闭环验收 | 若实际票未到，提前计了进项税，抵扣不合规（需业务上确保票货同行） | ✅ **P0 采用** |
| B 发票到才生成 | 入库只动库存，等发票模块再入账 | 严格贴合"取得扣税凭证才计进项税" | ① 本批**没有发票模块**→ 本批财务侧零凭证，闭环断链，验收不了 ② 库存已变、账未变，月末账实不符 | ❌ 不采用 |
| C 入库暂估 + 票到调整 | 入库生成「借存货 / 贷应付账款-暂估应付款」（**不含进项税**），取得扣税凭证后红冲暂估再正式入账 | 完全符合财会〔2016〕22 号 | 需要发票模块配合（第 2 批），本批无法闭环验证 | 🟡 **P1 预留分支** |

### 3.3.2 推荐方案与合规说明

**P0：默认走 A。** 业务前提是"**票货同行**"（中小企业采购的常见实际情形：供应商送货时随货开票）。为了让这个前提可被业务确认，**过账确认弹窗里放一个必看的勾选项**：

```
☑ 发票已随货到达（本次入库按可抵扣进项税入账）
☐ 发票未到（按暂估入账，不计进项税 —— 该能力将在第 2 批开放）
```
- 默认勾选第一项（对应 A 路径，第七章所有验收场景都基于此）；
- 若用户勾选第二项：本批**按钮置灰**，提示「暂估入库将在第 2 批（含发票管理）开放，本批请确认发票已到」。——这样既守住了准则，又不让开发在本批多写一条分支。
- **合规兜底**：入库单详情的过账轨迹里记录"发票已到"这一确认（谁在何时确认的），审计时可追溯到人；若事后发现票未到，由财务在当期用红字凭证 + 正式凭证调整。

**P1：** 打开暂估分支，分录为：
```
借  1405 库存商品（或物料配置的存货科目）      200.00
贷  2202.09 应付账款-暂估应付款                200.00     ← 注意：不估进项税（财会〔2016〕22 号）
```
第 2 批发票到达后：红字冲回上述暂估 → 按发票金额重新做「借存货 + 借进项税 + 贷应付账款」。

### 3.3.3 自动凭证的状态：直接"已记账"，不等人工审核

| 凭证来源 | 生成时状态 | 谁能改 | 理由 |
|---|---|---|---|
| **入库单自动生成** | **已记账**（直接进总账） | 谁都不能改，只能作废入库单红冲 | 库存与应付已生效，凭证必须同步生效。若允许"待审核"，则审核期间库存已变而账未变，报表必错 |
| 手工新增 | 草稿 → 已审核（需 `voucher:audit`）→ 已记账（需 `voucher:post`） | 草稿可改可删；已审核可反审核；已记账只能冲销 | 手工凭证没有业务单据背书，必须有人负责 |

> 财务主管"审凭证"的诉求通过两条满足：① 手工凭证的审核环节；② 对自动凭证的**抽查**（凭证查询 + 总账 + 科目余额表勾稽）。**不做**"自动凭证也需主管审核"——那会让月末存一堆待审凭证，库存和总账天天不平。

### 3.3.4 生成与冲销时机一览

| 业务动作 | 是否生成凭证 | 凭证类型 |
|---|---|---|
| 入库单**保存草稿** | ❌ | — |
| 入库单**过账** | ✅ | 正常凭证（蓝字） |
| 入库单**作废**（已过账） | ✅ | 红字凭证，金额取负 |
| 手工凭证保存 | ✅（草稿，不进总账） | 手工 |
| 手工凭证记账 | 进总账 | 手工 |
| 手工凭证冲销 | ✅ | 红字凭证 |
| 采购订单任何动作 | ❌ | 订单不产生会计影响 |

## 3.4 凭证科目映射

### 3.4.1 映射来源：一处配置，三处取值

| 凭证位置 | 取哪个科目 | 配置在哪 | 是否必填 |
|---|---|---|---|
| 借：存货 | `物料.存货科目` | 物料档案（E1-02） | **必填**（不填不许保存物料） |
| 借：进项税 | 系统参数 `erp.account.input_vat` 默认 `2221.01.01` | 系统参数 | 有默认值 |

| 贷：暂估应付（P1） | 系统参数 `erp.account.ap_estimate` 默认 `2202.09` | 系统参数 | 有默认值 |
| （预留）存货跌价等 | 不做 | — | — |

> **为什么不全放系统参数**：存货科目因物料类型而异（原料→1403 原材料，成品/外购商品→1405 库存商品），一个全局默认值不够用；应付科目因供应商而异（如预付为主的供应商走 2202 之外）。所以物料和供应商各存一个字段，参数只兜"全系统只有一种"的税科目。

入库单过账，按明细行逐行生成借方，按供应商汇总生成贷方：

贷：{供应商.应付科目}                    Σ行 amount_incl      （1 行，挂供应商辅助核算）

| 2 | 采购入库 GR-202610-0001 进项税额 | 2221.01.01 应交税费-应交增值税(进项税额) | 26.00 | | — |

### 3.4.3 科目校验（过账前必须全过，否则拒绝过账）

| 校验 | 不通过时的错误文案 |
|---|---|

### 3.4.4 配置怎么落到数据表（给 architect / backend 的落地口径）

| 配置项 | 存放 | 字段 |
|---|---|---|
| 物料 → 存货科目 | `erp_item.account_inventory_id` | 外键指向 `erp_account.id`，非空 |
| 供应商 → 应付科目 | `erp_supplier.account_payable_id` | 外键指向 `erp_account.id`，非空 |
| 进项税科目 | 系统参数（复用 `support/config`） | key `erp.account.input_vat`，存**科目编码**（不存 id，避免环境间 id 不一致） |
| 暂估应付科目（P1） | 系统参数 | key `erp.account.ap_estimate` |

> **参数里存科目编码而不是 id**：客户环境初始化时科目 id 会变，编码（2221.01.01）是稳定的。取用时"编码 → 科目"查一次并缓存。

### 3.4.5 辅助核算

- 科目可配置辅助核算类型（供应商/物料/仓库/部门），本批支持这 4 种。
- **凭证行必须写入辅助值**：借方存货行写 `item_id + warehouse_id`，贷方应付行写 `supplier_id`。凭证查询时双击分录可看到辅助值，并能按辅助值反查。
- 本批**科目余额表不做辅助核算展开**（E4-25 P1）。应付清单从 `erp_payable` 表直出，不依赖辅助核算余额——**这是刻意的**：应付清单是业务口径，科目余额是会计口径，两者分开算，再用 E4-27 勾稽检查对齐。

### 3.4.6 一张单多税率时的分录（必须做对，否则报税对不上）

入库单有 2 行：A 物料 100 件 @2.00（13%）、B 物料 10 件 @10.00（6%）

## 3.5 单据编号规则

### 3.5.1 业务单据编号

| 单据 | 格式 | 示例 | 重置周期 |
|---|---|---|---|
| 采购订单 | `PO-{YYYYMM}-{4位}` | `PO-202610-0001` | 按月 |
| 收货入库单 | `GR-{YYYYMM}-{4位}` | `GR-202610-0001` | 按月 |
| 应付明细 | `AP-{YYYYMM}-{4位}` | `AP-202610-0001` | 按月 |
| 物料 | `MAT-{6位}`（可由用户自定义格式） | `MAT-000001` | 不重置 |
| 供应商 | `SUP-{6位}` | `SUP-000001` | 不重置 |
| 仓库 | `WH-{2位}` | `WH-01` | 不重置 |
| 计量单位 | `UOM-{2位}` | `UOM-01` | 不重置 |

规则细节：
- **生成时机**：点「保存草稿」时就生成正式号（不是提交时）。理由：草稿也要能被引用/讨论；等到提交才取号会导致"两个人同时提交撞号"的体感。
- **实现**：`erp_doc_seq(doc_type, period, current_no)`，用 `UPDATE … SET current_no = current_no + 1 … RETURNING` 取号；因为取号与单据写入**在同一事务**，事务回滚时序号自动回退，**正常情况下不会跳号**。
- **极端情况允许跳号**：进程崩溃等异常仍可能缺号。不做好号回收（回收要额外锁和清理，且审计上"跳号"远比"重号"安全）。P1 提供「号段缺口检查」页。
- **月份归属**：按单据日期的年月取号。跨月补单（今天 11-02 补录 10-31 的单）→ 号是 `PO-202610-xxxx`，与日期一致。

### 3.5.2 凭证字号

| 项 | 规则 |
|---|---|
| 格式 | `记-{YYYYMM}-{4位}`，例 `记-202610-0001` |
| 号段 | **按会计期间**从 0001 起，一期一号段 |
| 连续性 | 期间内连续。**作废凭证占号不释放**（保留在表中 `status=作废`），这是会计档案完整性要求 |
| 红字凭证 | 单独占用新号（如 `记-202610-0009`），不写成"原号-红" |
| 凭证字 | 本批固定 `记`（记账凭证）。收/付/转 三种字第 2 批出现金银行收付时再引入 |

### 3.5.3 会计科目编码规则

```
一级科目：4 位数字                 例：1405、2202、2221
二级科目：一级 + "." + 2 位数字      例：2221.01
三级科目：二级 + "." + 2 位数字      例：2221.01.01
```
- `级次` = 编码段数（1405 → 1；2221.01 → 2；2221.01.01 → 3）；
- `父级` 由编码前缀自动推导（2221.01 的父级必须是 2221，且 2221 必须存在）；
- `是否末级` = 该科目下无子科目（新增子科目时自动把父级置为非末级，删除最后一个子科目时自动改回末级）；
- 编码唯一；**已被凭证使用的科目编码不允许修改**（只能停用后新建）。

### 3.5.4 主数据编码

- 用户手工录入，系统在新增弹窗里给一个"建议编码"（如 `MAT-000007`），可改；
- 编码规则可放宽为字母+数字+连字符，长度 ≤ 32；
- **保存后不可修改**（业务引用稳定性）。若确要改，只能停用旧编码 + 新建。

## 3.6 部分收货

### 3.6.1 规则

1. 一张采购订单可**多次收货**，每次生成**一张独立的入库单**，各自独立过账。
2. 每次过账独立产生：一批库存流水、一笔应付、一张凭证。**不做合并、不做暂存**。
3. 订单行维护 `received_qty`（已收数量），每次过账累加、作废时回退。
4. 订单状态由 `received_qty` 推导（**只由它推导，不允许手工改成"部分到货"**）：
   ```
   所有行 received_qty ≥ qty          → 全部到货
   存在任一行 received_qty > 0 但未达 → 部分到货
   全部行为 0 且已提交                → 已提交
   ```

### 3.6.2 算例：100 件分三次到货（60 / 30 / 10）

订单 `PO-202610-0002`：螺丝 M6×20，100 件 @2.00 不含税，13%，价税合计 226.00

| 次 | 入库单 | 数量 | 价款 | 税额 | 价税合计 | 结存(数量/金额/单价) | 累计应付 | 订单状态 |
|---|---|---|---|---|---|---|---|---|
| 1 | `GR-202610-0002` | 60 | 120.00 | 15.60 | 135.60 | 60 / 120.00 / 2.000000 | 135.60 | 部分到货 |
| 2 | `GR-202610-0003` | 30 | 60.00 | 7.80 | 67.80 | 90 / 180.00 / 2.000000 | 203.40 | 部分到货 |
| 3 | `GR-202610-0004` | 10 | 20.00 | 2.60 | 22.60 | 100 / 200.00 / 2.000000 | **226.00** | **全部到货** |

验算：`135.60 + 67.80 + 22.60 = 226.00` ✅；`120 + 60 + 20 = 200.00` ✅；`15.60 + 7.80 + 2.60 = 26.00` ✅

每次过账各生成一张凭证（共 3 张），3 张的借方存货合计 200.00、进项税合计 26.00、贷方应付合计 226.00 —— 与"一次性收货"完全等价。**这是部分收货设计的核心正确性判据，测试必须验这一条。**

### 3.6.3 超收控制

系统参数：

| 参数 | 默认 | 含义 |
|---|---|---|
| `erp.receipt.over_receive.allow` | `false` | 是否允许超收 |
| `erp.receipt.over_receive.ratio` | `0`（%） | 允许超收比例 |

校验公式（在**保存入库单时**和**过账时**各校验一次，防止保存后订单被改）：
```
允许上限 = 订单行 qty × (1 + ratio/100)
本次收货数量 ≤ 允许上限 − 已收数量 received_qty
```
| 情形 | 结果 |
|---|---|
| 不允许超收，本次 50 > 未收 40 | ❌ 拒绝：「本次收货 50 件超过订单未收数量 40 件。如需超收，请管理员在系统参数中开启超收」 |
| 允许 5%，订单 100、已收 60、本次 50 | 上限 = 100 × 1.05 = 105；可收 = 105 − 60 = 45 → 50 > 45，❌ 拒绝：「本次收货 50 件超过可收上限 45 件（订单 100 件、已收 60 件、允许超收 5%）」 |
| 允许 5%，订单 100、已收 60、本次 45 | ✅ 通过；订单行 received_qty 变 105，状态判为全部到货（**超收也算到货完成**） |

超收部分**照常生成应付与凭证**（货物真实收下了，钱真实要付），不做特殊处理。

### 3.6.4 关闭订单时的未收数量

点「关闭」并填原因后：剩余未收数量**直接作废**，不再允许建入库单。订单行 `received_qty` 保持不变（历史事实），状态=已关闭。若之后货又到了，只能走「手工新建入库单」（E3-03）并关联该订单（关联后仍会校验未收数量 → 所以实际要用"无订单的零星入库"），提示：「该订单已关闭，无法再收货；如需入库请用手工入库单并选择供应商」。

### 3.6.5 一张入库单能否跨多张订单？

**不能。** 一张入库单只归属一张采购订单（`receipt.po_id` 单值）。理由：过账时要回写订单收货数、要能反查来源，多订单混合会让"作废回退"变复杂。实际收货也很少混单。

## 3.7 作废与红冲

### 3.7.1 草稿状态：直接作废，无副作用

| 动作 | 允许条件 | 效果 |
|---|---|---|
| 删除草稿入库单 | `status=草稿` | 单据软删，无任何库存/财务/订单影响（草稿不占用订单未收数量） |
| 草稿作废 | 同上 | 保留单据痕迹，`status=已作废`，不在列表默认显示（可筛选查看） |

### 3.7.2 已过账状态：作废 = 红冲（一个事务，6 步）

**核心态度：已过账的单据一律不可修改、不可删除，唯一出路是作废（红冲）。** 这是"账要能查得住"的前提。

```
① 校验（任一不过 → 整体失败，无副作用）
   1. status = 已过账（已作废的不能再作废）
   2. 作废发现期（今天所属期间）未结账        → 见 3.8
   3. 无下游引用（本批无下游单据，留校验位）
   4. 库存充足：冲回后 qty ≥ 0，除非目标仓库 allow_negative=true
   5. 关联应付未付款（本批无付款，恒通过；第2批要加）

② 反向库存流水
   qty = −原入库数量；amount = −原入库金额（按原金额冲回，见 3.2.5 算例 3）
   重算结存：new_qty = old_qty + (−原数量)；new_amount = old_amount + (−原金额)
   new_avg = new_amount / new_qty（new_qty>0），否则 0

③ 生成红字凭证（见 3.7.3），记入"作废当天"所属期间
④ 应付冲销：原应付 status → 已冲销，unpaid_amount → 0.00（保留原金额备查）
⑤ 订单回退：订单行 received_qty −= 原入库数量；状态按 3.6.1 重算
   （全部到货 → 部分到货 / 部分到货 → 已提交）
⑥ 单据状态 → 已作废；记录 voided_by / voided_at / void_reason（必填，≥5 字）
```

**算例（第三章验收场景 3 的数据基础）**：
- `GR-202610-0001` 已过账：螺丝 100 件，价款 200.00，税 26.00，应付 226.00；当前库存 100 / 200.00 / 2.000000
- 作废后：库存 0 / 0.00 / —；流水新增一行 `-100 / 2.000000 / -200.00 / 结存 0 / 0.00`；红字凭证 `记-202610-0002`；应付 `AP-202610-0001` 状态=已冲销；订单 `PO-202610-0001` 从"全部到货"退回"已提交"

**库存不足的拒绝例子**：若这 100 件已被后续单据消耗 60 件（第 3 批生产领料），现结存 40：
> ❌ 「无法作废：该入库单冲回后库存将为 −60 件（当前结存 40，本次冲回 100），且仓库 WH-01 不允许负库存。请先处理引用该库存的后续单据。」

### 3.7.3 红字凭证规则

**红字凭证 = 科目相同、方向相同、金额取负**（会计上的红字冲销，不是"反向分录"）。

| 项 | 规则 |
|---|---|
| 生成方式 | 业务类（入库作废）自动生成；手工凭证冲销手动触发（E4-11） |
| 金额 | 各分录行金额 = 原行金额 × (−1)，借贷方向**保持不变**；合计仍平衡（负数对负数） |
| 科目 | 与原凭证完全相同 |
| 辅助核算 | 与原行相同（否则按辅助核算查明细会对不上） |
| 字号 | 新号（期间内顺延），不写"原号-红" |
| 摘要 | `冲销 记-202610-0001（GR-202610-0001 采购入库作废）` |
| 关联 | 红字凭证记 `reverse_of_voucher_id` = 原凭证 id；原凭证 `status=已冲销` |
| 进总账 | ✅ 参与本期借/贷合计（负数），因此本期借方 = 200.00 + (−200.00) = 0.00 |
| 原凭证 | 不删除、不修改金额，只改状态并保留全部信息（审计要求） |
| 跨期 | 红字凭证记入**执行冲销的当天所属期间**。若原期间已结账 → 只能记当期（这会形成跨期调整，属正常会计处理），并在凭证摘要注明原期间 |
| 禁止 | 红字凭证不能再被冲销（防循环）；已冲销的原凭证不能再冲第二次 |

### 3.7.4 手工凭证的冲销

财务在凭证列表对 `已记账` 凭证点「冲销」→ 弹窗填冲销原因 → 生成红字凭证 + 原凭证标记已冲销。与业务类的区别仅在于"触发人"，规则完全一致。

## 3.8 期间控制

### 3.8.1 期间模型

| 项 | 规则 |
|---|---|
| 期间粒度 | **自然月**，`YYYYMM` |
| 生成 | 系统初始化时生成**当年 12 个**，每年 1 月 1 日（或首次登录）自动补下一年 |
| 状态 | `1=未结账` / `2=已结账` |
| 本批能力 | **只读列表 + 校验**。不提供结账/反结账按钮（第 4 批 E4 报表与结账） |

### 3.8.2 校验点（三处，缺一不可）

| # | 动作 | 取哪个日期定期间 | 已结账时 |
|---|---|---|---|
| 1 | 入库单**过账** | 入库单的 `receipt_date` | ❌ 拒绝 |
| 2 | 凭证**保存/记账** | 凭证的 `voucher_date` | ❌ 拒绝 |
| 3 | 入库单**作废（红冲）** | **执行作废的当天** | ❌ 拒绝 |

错误文案：
> ❌ 「会计期间 2026-09 已结账，禁止新增或修改凭证。如需调整，请联系财务主管在未结账期间处理。」

### 3.8.3 本批的现实情况与必须埋的坑

- **本批没有结账功能，所以所有期间都是"未结账"**，上述校验永远不会真正拦住人 → 但代码必须先写好，第 4 批开结账时立即生效，不需要回头改业务代码。
- 由此带来一个本批的**已知风险**（要写进测试范围）：用户可以修改入库单日期把凭证做到上个月。本批接受（因为上个月也没结账，账是平的），但**测试要验证**：把 `receipt_date` 改成 2025 年的日期时，若该期间不存在则拒绝，提示「目标期间 2025-06 不存在，请先初始化该年度期间」。
- 日期可选的合理范围：`今天 − 365 天` 至 `今天 + 90 天`（前端日期控件限制 + 后端校验），避免误填 1900 年。

### 3.8.4 本期借方/贷方/期初/期末的定义

```
期间 = 2026-10
期初余额 = 该科目在 2026-10-01 之前所有已记账凭证的（借 − 贷）净额，按科目方向呈现：
           借方科目：期初 = 借累计 − 贷累计
           贷方科目：期初 = 贷累计 − 借累计
本期借方 = Σ 期间内该科目所有已记账凭证行的借方金额
本期贷方 = Σ 期间内该科目所有已记账凭证行的贷方金额
期末余额 = 期初 ± （本期借 − 本期贷），按方向呈现；红字凭证的负金额自然参与合计
```
> 期初一律取"累计净额"，不做"上月期末结转"的物理动作（避免跨期结转表把数算错）。这样任何期间随时可算，也不会因为补录上期凭证导致下期期初错乱（第 4 批结账后再引入物理结转）。

## 3.9 多仓库

### 3.9.1 记账粒度

- 库存与成本**按（物料 × 仓库）独立记账**。同一物料在 WH-01 结存单价 2.00、在 WH-02 可能是 2.30，这是正确的，不做全公司统一价。
- 库存表主键 = `(item_id, warehouse_id)`。
- 入库单的仓库在**表头**（一张单只能收进一个仓库），明细不带仓库。理由：一次到货进一个仓是常态；若要分仓，就开两张单——这也让"作废一张单"的边界清晰。

### 3.9.2 本批的仓库相关约定

| 项 | 约定 |
|---|---|
| 调拨 | **不做**（第 4 批或按需） |
| 物料.默认仓库 | 只用于"新建单据时预填仓库"，**不约束**业务（可以收进别的仓） |
| 仓库.允许负库存 | 默认否。允许时，作废/出库可把结存做成负数；入库时若结存≤0 则重置单价（3.2.6） |
| 安全库存 | 存在**物料级**（`item.safety_stock`），预警时与每个仓库的现存量比较。按仓库单独设安全库存列 P1 |
| 仓库负责人 | 用于"仓管员只能操作自己仓库"的数据权限（5.3.2），同时是预警的默认通知对象（本批不做通知，只显示在预警列表） |
| 有库存的仓库 | 禁止停用（E1-11） |

### 3.9.3 同一物料多仓的库存展示

即时库存列表按 （物料, 仓库） 一行展示，同一物料会有多行。列表支持「按物料汇总」开关（P1）：把同一物料的多仓合成一行显示总数量/总金额，展开看分仓明细。

### 3.9.4 批次字段预留（本批不做，但字段必须先留好）

| 表 | 预留字段 | 本批取值 | 第 3 批启用方式 |
|---|---|---|---|
| `erp_receipt_item` | `batch_no VARCHAR(64)`、`production_date DATE`、`expiry_date DATE` | 恒 NULL，UI 隐藏 | 打开 UI 字段即可，**不改表结构** |
| `erp_stock_flow` | `batch_no VARCHAR(64)` | 恒 NULL | 同上 |
| `erp_stock_balance` | 主键需扩展为 `(item_id, warehouse_id, batch_no)` | `batch_no` 恒 NULL，唯一索引按三元组建（NULL 视为同一批，PG 需注意 NULL 唯一性） | 打开批次维度后无需改主键 |

### 4.2.4 明细行编辑体验（本批交互质量的关键，逐条可验收）

| # | 行为 | 具体表现 |
|---|---|---|
| **I-01** | 物料搜索 | 在物料格输入 `螺丝` 或 `M6` 或 `LS`（拼音首字母）都能搜到；下拉项显示 `MAT-000001 螺丝 M6×20 / M6×20 / 件`；**列表最多 20 条 + "输入更多字符继续搜索"** |
| **I-02** | 选完物料自动带出 | 规格、单位、税率立刻填充；**焦点自动跳到下一格（数量）**，不用鼠标点 |
| **I-03** | Enter = 确认并向右 | 在任意可编辑格按 `Enter`：确认当前值 → 焦点移到右侧下一个可编辑格 |
| **I-04** | 行尾 Enter = 新行 | 在最后一行的最后一格按 `Enter`：自动新增一行，**焦点落在新行的物料格** |
| **I-05** | Tab 行为 | 同 Enter（向右），到行尾换行首（符合表格编辑直觉）；`Shift+Tab` 反向 |
| **I-06** | ↑↓ 跨行 | 在数量/单价/税率三列按 `↑↓` 在同列上下行移动，适合批量填同一字段 |
| **I-07** | 自动算金额 | 数量或单价或税率任一变化 → 本行金额/税额/价税合计即时重算（前端计算，**无需等后端**）；同时在合计条同步（**输入停顿 200ms 后更新，防止每敲一个数字都闪**） |
| **I-08** | 数量/单价格式化 | 失焦或回车时格式化：数量 `100.0000` → `100`；单价 `2` → `2.0000` |
| **I-09** | 空行处理 | 最后一行的物料为空时，不参与合计、不参与提交校验；保存草稿时**自动丢弃完全空白的行** |
| **I-10** | 删除行 | 点 🗑 → 若该行有内容，弹「确认删除第 2 行（螺丝 M6×20，100 件）？」；空白行直接删，不弹 |
| **I-11** | 重复物料提示 | 同一单内重复选同一物料时不阻断，但在该行行号旁显示一个淡橙 `!` 图标，hover 提示「该物料在本单第 2 行已出现」 |
| **I-12** | 校验时机 | **失焦时软提示**（红框 + 字段下方小字），**提交时硬拦截**（汇总一个错误清单弹窗：「第 2 行数量必须大于 0」）。不搞"边打字边报错" |
| **I-13** | 合计条 | 固定在视口底部（`position: sticky`），四组数字：数量合计 / 金额合计 / 税额合计 / 价税合计（漂木棕 18px 加粗） |

**空态**：明细区无行时显示虚线框 `[＋ 添加第一行]` + 提示「也可以从「未清订单」里选一张单复制明细」（P1）。

**设计要点（每条都是给前端的硬要求）**
1. **三块信息缺一不可**：库存变化（含单价前后对比）、应付、凭证分录。这是仓管"看懂自己做了什么"的全部依据。
2. **凭证预览必须是真实计算的结果**，不是写死的模板文案——它同时也是后端过账逻辑的一次前端预演；若前后端算出的凭证不同，说明有 bug（建议用同一个映射函数，后端暴露一个 `preview` 接口）。
3. 「发票已随货到达」勾选框**默认勾选**、不可不选（取消勾选则弹「本批暂不支持暂估入库，请确认发票已到」并自动勾回）。
4. 金额校验不通过时，这里就直接拦住（不等到后端报错）。
5. 点「确认过账」后按钮进入 loading 态并**禁用**（防连点），成功 toast「过账成功，已生成凭证 记-202610-0001」+ 顶部出现"凭证"链接。
6. 过账失败 → 弹窗不关，顶部红条显示具体原因（4.6 的文案），可重试。

## 4.5 统一交互规范（跨页复用，开发按这一节实现一次即可）

### 4.5.1 单据类页面的统一按钮条

| 位置 | 按钮 | 出现条件 |
|---|---|---|
| 左上 | `← 返回` | 恒在 |
| 中间 | 单据号 + 状态标签 + 口径徽标（订单） | 草稿显示「草稿·无单号」 |
| 右上 | `保存草稿`（default）`提交/过账`（primary）`作废`（danger 描边）`打印` | 按状态机 + 权限显隐（`v-privilege`） |

### 4.5.2 敏感按钮的保护（三重）

1. **不渲染**：无权限时按钮不出现在 DOM（`v-privilege`），不是置灰——置灰会让用户反复点。
2. **二次确认**：过账/作废/冲销/关闭订单 全部弹确认框，说清影响。
3. **后端硬校验**：接口层 `#[alun::permission]` + 业务校验（状态、期间、库存），前端永远不是唯一防线。

### 4.5.3 状态变更后的列表刷新

任何写操作成功后，**返回列表页时列表必须重新拉取**（不能靠前端本地改状态），避免"列表看着还是草稿，点进去已经过账"。

### 4.5.4 并发编辑保护

单据/凭证保存时带 `updated_at`（或版本号）；若期间被别人改过 → 拒绝并提示：
> 「该单据已被 王五 于 14:32 修改，请刷新后重试。」

### 4.5.5 空态 / 加载 / 异常

| 场景 | 表现 |
|---|---|
| 列表加载中 | t-loading 骨架屏（表格 5 行灰条），不用转圈 |
| 列表无数据（无筛选） | 插画 + 「还没有数据」+ 主按钮（如「+ 新建采购订单」） |
| 列表无数据（有筛选） | 「没有符合条件的记录，试试清空筛选条件」+ `清空筛选` 按钮 |
| 接口失败 | 表格区中央：「加载失败：{原因}」+ `重试` 按钮；**不清空已加载数据** |
| 保存中 | 按钮 loading + 全局禁止重复提交 |
| 提交后网络超时 | 提示「提交结果未知，请刷新列表确认，不要重复提交」——**这条对过账尤其重要**，避免用户重复点导致重复入库（后端需保证幂等：同一入库单重复过账请求返回"已过账"而不是再入一次库） |

### 4.5.6 过账的幂等要求（给后端）

同一个入库单的过账请求必须是**幂等的**：若单据状态已是「已过账」，再次请求直接返回当前结果（不报错、不重复入库）。实现建议：过账入口对单据行加 `FOR UPDATE` 并校验状态，前端也在成功后将按钮置为不可用。

# 五、权限模型

## 5.1 权限码命名（与菜芦现有规范、与审批流 PRD 保持一致）

### 5.1.1 格式：四段

```
business : erp : {资源} : {动作}
   ①        ②       ③        ④
```
| 段 | 取值 | 说明 |
|---|---|---|
| ① 模块 | `business` | 与 `sys_menu.module_code='business'` 一致（现有只有 system / support，这是第三个，F1） |
| ② 业务域 | `erp` | business 下与 `workflow` 并列的子域 |
| ③ 资源 | 见 5.1.2 | 13 个资源 |
| ④ 动作 | 见 5.1.3 | 复用现有动作词汇 |

> **为什么必须四段**：ERP 有 13 个资源、70 个权限点。硬塞三段只能写成 `business:erp:po-list` 这种"动作里塞资源"的畸形码，或退化成 `business:erp:list` 一个码管所有列表，粒度粗到做不了按钮级鉴权。四段是对现有格式的**受控扩展**：不改表结构（`auth_code VARCHAR(100)` 够）、不改匹配逻辑（仍是全等匹配，F5）。
>
> **与审批流 PRD 的一致性**：同一产品内两套权限码命名风格必须一致，否则运维在角色授权页会看到 `business:workflow:def:list` 和 `business:erp:po-list` 两种写法并存。本文与之一致采用四段。

## 5.3 数据权限（F9 约束下的唯一正确做法）

### 5.3.1 硬约束

`sys_role` **没有 data_scope 字段**（F9）。所以**不能**在角色表上加"数据范围"配置了事，必须在 **ERP 服务层**用"权限码 + 业务表关联"实现过滤。给 archiect 的提醒：不要在 `sys_role` 上加字段——那会动到现有 system 模块的 DDL 与前端角色表单，影响面远超本批。

### 5.3.2 三条规则

| 角色 | 能看到什么 | 实现方式 |
|---|---|---|
| **采购员** | **默认只看自己创建的采购订单**；有 `po:view-all` 则看全部 | `erp_po.created_by = 当前用户` 作为默认过滤条件；列表页「只看我的」开关默认开，但若用户无 `view-all` 权限则**该开关隐藏且强制过滤**（不能靠前端开关当权限） |
| **仓管员** | **只能对"被指派的仓库"建单/过账/作废**；列表只显示这些仓库的单据（无 `stock:view-all-warehouse` 时） | 新增关联表 `erp_warehouse_user(user_id, warehouse_id)`（5.3.3）；入库单的仓库下拉只列绑定仓库 |
| **财务会计 / 财务主管** | **全部数据**（含所有仓库、所有采购员的订单） | 直接授予相应权限码，不做数据过滤 |
| **老板/管理层** | **全部数据，但只读** | 只授 `list` / `detail` / `*:view` / `stock:cost`，**不授**任何 `create`/`update`/`post`/`void`/`reverse` |
| **管理员（IT）** | 全部数据 + 主数据维护 | 授全部 P0 码；但**不建议**给 IT `receipt:post` / `voucher:reverse`（财务责任要落到财务的人身上） |

### 5.3.3 唯一的 ERP 自建关联表：`erp_warehouse_user`

| 字段 | 说明 |
|---|---|
| `user_id` | 复用 `sys_user.id`，不建用户体系 |
| `warehouse_id` | `erp_warehouse.id` |
| `created_at` / `create_by` | 审计 |

- 主键 `(user_id, warehouse_id)`；
- 维护入口：**仓库档案 → 编辑 → 「仓管员」多选**（比单独做一个"仓库授权"页更省一个菜单；若一个仓有多人管，就都选上）；
- 一个用户可绑定多个仓库；**未绑定任何仓库 ≠ 能看全部**，而是"一个都看不到"（安全默认）。前端表现为入库单页面的仓库下拉为空 + 提示 M-17。

### 5.3.4 服务层实现要点（不写代码，只给口径）

1. 用户登录后，`/me` 接口除返回权限码外，**额外返回 `warehouse_ids` 与 `can_view_all_po` 两个业务字段**（放在现有 `/system/auth/me` 的响应扩展里，或单独 `/business/erp/context` 接口——建议后者，不动现有 auth 契约）。
2. 所有列表接口在构造 SQL 时**统一走一个数据范围过滤器**：把 `created_by = ?` / `warehouse_id IN (...)` 作为 `WHERE` 条件注入，**不是**在拿到结果后再内存过滤（后者分页会错）。
3. 单条详情接口也必须校验（防止有人直接改 URL 里的 id 越权查看）。
4. 过账/作废接口校验 `单据仓库 ∈ 我的仓库`，不通过返回 403 + 文案 M-16/M-17。

### 5.3.5 UI 上的隔离必须说清楚

列表页顶部常驻一行浅灰提示（雾蓝灰，12px）：
> 「当前数据范围：WH-01 主仓、WH-02 次仓（共 2 个仓库）」
或
> 「当前数据范围：仅我创建的采购订单」

**这一行不是装饰**：不做这行提示，仓管员会以为"系统里没有这些单据"，反复找 IT 报故障。

## 5.4 敏感操作（必须单独授权，默认谁都不给）

| 敏感操作 | 权限码 | 为什么敏感 | 建议授予 |
|---|---|---|---|
| 入库单**过账** | `receipt:post` | 一次性改变库存、应付、总账三本账 | 仓管员（限本仓）+ 财务主管 |
| 入库单**作废**（红冲） | `receipt:void` | 可反向篡改已入账数据 | 仓管主管 / 财务主管，**不建议给一线仓管** |
| 凭证**审核/反审核** | `voucher:audit` | 复核关口 | 财务主管 |
| 凭证**记账** | `voucher:post` | 决定什么进总账 | 财务主管 / 会计 |
| 凭证**冲销** | `voucher:reverse` | 直接影响报表 | 财务主管，**不给会计** |
| 科目**维护**（增删改停用） | `account:create/update/delete/disable` | 科目结构错 = 账套报废 | 财务主管 / IT，**不给会计日常使用** |
| 看**成本单价** | `stock:cost` | 成本是商业敏感信息 | 财务、管理层；仓管默认不给 |

**审计要求**：以上 7 类操作全部写操作日志（复用 `sys_audit`），记录 谁/何时/哪张单/改前改后/原因（作废与冲销必填原因）。

# 六、菜单结构

## 6.1 决策：1 个一级目录「ERP」+ 4 个二级分组（D3）

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| ① 4 个一级目录（采购/库存/财务/基础资料） | 与现有「系统管理」「支撑功能」平级 | 点两下就到页面；实现最简单 | 第 2/3/4 批加"销售管理""生产管理""报表"后，**顶部一级导航会膨胀到 8~9 个**，与现有 2 个目录的视觉比例完全失衡 | ❌ |
| ② **1 个一级目录「ERP」→ 4 个二级分组 → 页面 → 按钮** | 收进一个入口 | 顶层永远只多 1 个目录；后续批次只增二级，不增一级；心智清晰（"ERP 里什么都有"） | 到页面点三下；依赖二级目录的嵌套渲染 | ✅ **采用**（技术可行性已核实：`SideMenuItem` 递归，F7） |
| ③ 1 个一级目录，页面全部平铺为二级 | 不分组建 | 点两下到页面 | 第 1 批就有 14 个平铺菜单，第 2 批变 25 个，侧边栏一屏放不下 | ❌ |

**⚠️ 若前端实测二级目录（目录套目录）渲染有样式问题**，降级方案：把 4 个分组目录改成 4 个一级目录（`parent_id` 置 NULL、`sort_order` 40/50/60/70），**只改种子数据的两列，零代码改动**。这就是选方案 ② 也不锁死的原因。

## 6.4 与现有菜单共存的 3 个注意点

1. **`module_code='business'`**：现有 `sys_menu.module_code` 注释只写 `system / support`，但字段是 `VARCHAR(20)`，填 `business` 合法。**必须检查「菜单管理」页的模块下拉是否需要加上 `business` 选项**，否则管理员按模块筛选时看不到 ERP 菜单（F1 的既有假设）。
2. **`sort_order=40`**：现有 system=10、support=20、协同办公（审批流 PRD 占位）=30 → ERP 放 40。若老大要求 ERP 更靠前，改成 25 即可（不影响其它逻辑）。
3. **`auth_code=''` 的目录**：一级目录 ERP 与 4 个分组目录的 `auth_code` 留空串（`hasPermission('')===true`，F5），这样任何登录用户都能看到"ERP"入口、但点开只看到自己有权限的页面；若某分组下一个页面都没权限，该分组目录与 ERP 目录会自动整体隐藏（F6），不会出现空目录。
